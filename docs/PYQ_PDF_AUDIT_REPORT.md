## 1. Executive Summary

A comprehensive, end-to-end audit and repair was conducted on all Previous Year Question (PYQ) paper records, associated local storage files, backend pipelines, and frontend interfaces in FlashFacts.

Before this intervention, several critical structural defects existed:
1. **Misleading Local PDF Files**: 8 local files (~2.6 KB each) existed in `data/pyq_pdfs/`. These were synthetic single-page test mockups generated by an earlier prototype script rather than genuine, multi-page official question paper booklets published by examination authorities.
2. **Homepage-Only Source Links**: 5 out of 8 records pointed to generic commission root homepages (e.g. `https://www.tnpsc.gov.in`, `https://ssc.gov.in`, `https://www.rrbcdg.gov.in`) rather than specific official examination paper archive URLs.
3. **Misleading Metadata & PDF URLs**: Two UPSC CSE Prelims papers pointed to Civil Services Mains PDF filenames (`QP-CSM-...`), and records presented synthetic file sizes (e.g., 2.6 KB) to frontend users despite lack of genuine local booklets.
4. **Pipeline Vulnerabilities**: The download and view endpoints lacked multi-tier structural validation, permitting HTML or truncated files to be served if saved with a `.pdf` extension.

### Corrective Actions Taken
- **Database Backup**: Created an immutable baseline JSON backup at `backups/pyq_papers_baseline_20261026_150738.json`.
- **Synthetic Stubs Cleansed**: Archived all 8 synthetic 1-page stubs out of active production storage into `data/pyq_pdfs_synthetic_archive/`. Cleared false `storage_path`, `checksum_sha256`, and `file_size_bytes` from the database.
- **Official Source Deep-Links Established**: Updated all records to authoritative, specific question-paper archive and portal pages on TNPSC, UPSC, SSC, and RRB.
- **Accurate Classification**: Classified all 8 records as **Verified official source-link-only papers** (`availability_status="source_link_only"`, `verification_status="verified_official"`, `redistribution_status="unknown"`).
- **Hardened PDF Pipeline**:
  - Implemented multi-stage PDF verification: magic byte `%PDF-` signature check, HTML/XML error rejection, `pypdf` structural page extraction, fallback `%%EOF`/`/Catalog` validation, and file size boundary enforcement (10 B to 50 MB).
  - Hardened path traversal defense against null bytes, parent path traversal (`..`), and directory breakout.
  - Restricted external redirects strictly to approved HTTPS authority hosts (`*.tnpsc.gov.in`, `*.upsc.gov.in`, `*.ssc.gov.in`, `*.ssc.nic.in`, `*.rrbcdg.gov.in`).
- **Frontend Realignment**:
  - Paper cards display accurate status pills ("Verified Local PDF" vs "Official Portal Link").
  - File size and SHA-256 are rendered **only** when a validated local PDF actually exists on disk.
  - For source-link-only papers, the UI provides a direct "Open Official Source" button and provenance viewer, disallowing deceptive local viewer/offline cache attempts.
- **Automated Verification**:
  - Expanded `tests/test_pyq_papers.py` from 11 to 27 tests covering HTML rejection, traversal variants, checksum accuracy, source-link-only behavior, and restricted document defense.
  - All 126 backend tests passed (`126 passed`).
  - Next.js production build succeeded (`16/16` routes statically and dynamically generated with zero TypeScript errors).

## 6. Protocols for Future Paper Additions

When expanding the PYQ library with new examination papers:
1. **Never substitute synthetic stubs or AI-generated PDFs**.
2. **Never register root homepages** (e.g. `tnpsc.gov.in`); always use specific examination paper, tentative answer key, or archive endpoints.
3. If hosting a local copy, confirm open-access redistribution rights (`redistribution_status="official_open_access"`). Compute SHA-256 and byte sizes strictly from the verified binary.
4. If rights are uncertain or prohibited by commission terms, configure the paper as `availability_status="source_link_only"`, keeping `storage_path=None` and pointing users directly to the commission's official portal.
